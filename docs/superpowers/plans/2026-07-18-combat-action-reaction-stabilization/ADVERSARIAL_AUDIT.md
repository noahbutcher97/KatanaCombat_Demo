# Adversarial Audit: Combat Action And Reaction Stabilization

Date: 2026-07-19

Scope: Master design, eight micro-specs, master implementation plan, and eight micro-plans
Disposition: No open high/medium planning finding; listed runtime proofs remain mandatory

## Method

The review treated every external call as reentrant, every callback as stale until identity is proven, every montage/StateTree task as presentation or transport rather than gameplay authority, every binary asset operation as capable of saving unintended packages, and every test as a possible false positive. Findings were checked against current project source, canonical defense/paired docs, official Epic documentation, and installed UE 5.6 source.

| H12 | Reverse queue iteration can start multiple montages from one phase boundary and mutate the collection/state during reentrant montage callbacks. | 04A selects/removes exactly one winner before external calls and defers remaining input behind the new owner. | multi-entry boundary and synchronous montage-end reentry tests. |
| H13 | Missing Enhanced Input terminal bindings can leave direction or held attack/block state latched after release, input flush, or context removal. | 02 binds Move Completed/Canceled for canonical facing/steering state; 04A binds attack/Block Canceled and distinguishes physical release from cancellation so cancellation cannot fabricate a hold follow-up. | zero-direction release, mapping rebuild, input flush, and idempotent cleanup tests. |

| H15 | Treating immutable attack-edge intent as the only rotation signal would make queued attacks deterministic but still deny the player control during an active warped turn; replacing it with live input would make queue/preflight behavior nondeterministic. | 02 separates immutable base intent from a terminal-aware live steering sample. | H16 | A generic live-input field on shared alignment requests could steer guard, parry, paired counter, finisher, defense, or AI alignment and break synchronized positioning. | Steering is admitted only for the exact `ActiveAttackWarp` player owner with bound attack/montage identity; all other priorities and AI are closed to it. | simultaneous input during every excluded alignment class produces zero contribution. |
| H17 | Input accepted late in the warp can move the target beyond what remains reachable before damage, invalidating strict startup preflight and producing a miss or snap. | The pure resolver clamps every update by remaining simulation time, rate, cumulative budget, and tolerance, then freezes at the effective damage deadline with a reason code. | just-before-contact changes at several rates/play rates remain reachable without transform writes. |

## Accepted Low-Risk Deferrals

These are intentionally outside the implementation plan and must not be described as current functionality:

- EQS tactical orbit scoring.
- RVO or Detour Crowd avoidance and group angular-slot coordination.
- Additive flinch effects on weapon trace trajectory, hit confidence, or damage scale.
- Renaming serialized `StaggerPower` or `HitStunDuration` properties before migration evidence.
- Migrating the existing primary lane away from `DefaultGroup.DefaultSlot`.
- Multiplayer replication, prediction, rollback, and packaged-build certification.
- Production-quality replacement art beyond the reviewed project-owned proof assets.

## Per-Slice Hostile Checklist

Before each commit, challenge:

1. null/stale participants and exact owner generation;
2. synchronous destruction from damage, montage, stop, or delegate calls;
3. duplicate, out-of-order, skipped, and late callbacks;
4. death/paired precedence and missing presentation;
5. owner-only token, focus, speed, alignment, timer, and notify cleanup;
6. a legacy C++, Blueprint, StateTree, notify, or generic damage path bypassing the new policy;
7. non-finite data, empty tags, default-valued assets, and fallback ambiguity;
8. false proof from stale binaries, wrong test root, source-only checks, or unsaved Editor state;
9. dirty user map/package hashes and exact staged paths;
10. whether the diff still satisfies the initiating crash and gameplay notes rather than only its local tests.
11. whether capture, decision, application, and visible result were accidentally conflated in telemetry or acceptance claims;
12. whether a normal input, stale Enhanced Input edge, or synthetic queue entry can bypass exact hold ownership.
13. whether logs identify actor and exact generation, and whether each advertised debug CVar actually enables its diagnostics.
14. whether live steering changed immutable base intent, target/translation identity, non-regular alignment, or published an unreachable/noisy target.

Any newly discovered high/medium finding reopens the owning micro-spec and plan before implementation continues.
