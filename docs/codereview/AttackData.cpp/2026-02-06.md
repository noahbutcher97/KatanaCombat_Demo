# Code Review: AttackData.cpp (2026-02-06)

## 1. Objective
Data Asset implementation for attack properties. Includes critical runtime logic for notify extraction, combo chain validation, and montage section management.

## 2. Scope
Timing calculation, Notify validation, and Circular dependency tracking.

## 3. Metrics & Standards
*   **Metrics**:
    *   Complexity: Medium.
    *   Test Coverage: Medium (Chain validation covered).
*   **Standards Adherence**:
    *   Patterns: 🟢 Excellent use of depth-first search for cycle detection.

## 4. Code Organization
*   **Component Cohesion**: Good. Keeps configuration and validation logic together.

## 5. Key Areas
*   **Functionality**:
    *   `GetSectionTimeRange`: Supports both chronological and non-chronological sections, ensuring robust timing extraction even if montage sections are rearranged.
    *   `HasValidNotifyTimingInSection`: Correctly bridges the gap between modern `AnimNotify_AttackPhaseTransition` and deprecated legacy notifies.
    *   `IsDataValid`: Orchestrates the entire validation pipeline (`DetectCycles`, `ValidateTerminalTag`).
    *   `DetectCycles`: Prevents stack overflow and infinite loops in the combo chain resolution.
*   **Performance**:
    *   Uses an **O(1) fast path** for section lookup when sections are chronologically ordered, falling back to O(N) only when necessary.
*   **Readability**: High. Complex validation logic is cleanly partitioned into helper functions.

## 6. Gaps & Bugs

### GAP-1: String-based Error Filtering
*   **Priority**: Low | **Impact**: Maintainability
*   **Description**: `IsDataValid` uses string matching (`StartsWith`) to filter validation errors. This is fragile if asset naming conventions change.
*   **Fix**:
    *   **Rationale**: Robustness.
    *   **Action**: Switch to a more structured error reporting system using `FDataValidationContext` structured sub-objects if possible.

### GAP-2: Weapon-Type Finishers (Gap 10.3)
*   **Priority**: 🟡 **Medium** | **Impact**: Variety
*   **Description**: Currently assumes a 1:1 mapping for finishers. Needs support for selecting finishers based on the equipped weapon type.
