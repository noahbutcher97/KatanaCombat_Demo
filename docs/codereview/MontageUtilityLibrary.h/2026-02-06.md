## 5. Key Areas
*   **Functionality**:
    *   `DiscoverCheckpoints`: Crucial for parsing montage data. It combines inferred windows from `AnimNotify_AttackPhaseTransition` with explicit `AnimNotifyState_ActionWindow_Base` subclasses. It also needs to correctly reflect the shift to `AnimNotify_HoldWindowStart` for hold mechanics.
    *   `ResolveNextAttackContextual`: Implements the priority-based logic for determining the next attack in a combo.
    *   `CalculateChargeLevel`: Provides advanced hold mechanics for scaling attacks based on hold duration.

## 6. Gaps & Bugs

### GAP-1: Deprecated Hold Window Discovery
*   **Priority**: 🟡 **Medium** | **Impact**: Documentation Clarity / Code Cleanliness
*   **Description**: While `AnimNotifyState_HoldWindow` is deprecated, `DiscoverCheckpoints` still explicitly scans for `AnimNotifyState_ActionWindow_Base` subclasses and logs them, which could include the deprecated hold window.
*   **Fix**:
    *   **Rationale**: The new hold mechanic is event-driven via `AnimNotify_HoldWindowStart`. The `MontageUtilityLibrary` should primarily be concerned with phase transitions and explicit non-hold windows (Parry, Combo).
    *   **Action**: Either modify `DiscoverCheckpoints` to specifically ignore `EActionWindowType::Hold` for `AnimNotifyState`s or ensure all `UAnimNotifyState_HoldWindow` instances are purged from montages and the class eventually removed. The `CombatComponent` directly processes the `OnHoldWindowStart` event.
