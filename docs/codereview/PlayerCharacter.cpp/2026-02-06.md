# Code Review: PlayerCharacter.cpp (2026-02-06)

## 1. Objective
Implementation of the playable character. Binds input actions to the Combat Component.

## 2. Scope
Input handling and component initialization.

## 3. Metrics & Standards
*   **Standards Adherence**: 🟢 Correct use of `EnhancedInputComponent`.

## 4. Key Areas
*   **Functionality**: Captures `LastMovementInput` during `Move()` which is used by attack handlers.

## 5. Gaps & Bugs

### GAP-1: Context Delay
*   **Priority**: 🟡 **Medium** | **Impact**: Responsiveness
*   **Description**: `OnLightAttackPressed` calls `OnInputEventAuto` which samples `LastMovementInput`. This sampling happens at the exact moment of the press. However, for "Hold" attacks, the direction is needed at *release*. 
*   **Issue**: If the player changes stick direction *during* the hold, the initial press direction might be stale by the time the resolution happens.
*   **Fix**: The `CombatComponent` now correctly uses its own `DirectionalInputBuffer` at release, but `PlayerCharacter` still passes `LastMovementInput` on press. This redundant data should be removed to avoid confusion.

## 6. Action Items
*   **[Cleanup]**: Transition all attack input calls to a directionless `OnInputEvent` and let the component handle directional sampling via context switching.
