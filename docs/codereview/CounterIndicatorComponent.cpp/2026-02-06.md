## 6. Gaps & Bugs

### BUG-1: Direct use of `SetTintColorAndOpacity` can lead to visual inconsistencies.
*   **Priority**: 🟡 **Medium** | **Impact**: Visual Inconsistency
*   **Description**: The `ApplyColor` function directly calls `SetTintColorAndOpacity` on the `UWidgetComponent`. This assumes the underlying `UUserWidget` (which is set via `IndicatorWidgetClass`) respects this property and applies it to its visual elements. Many UMG widgets might have their own internal color-changing logic, or may not use a tintable root widget.
*   **Fix**: Implement a more robust solution by exposing a BlueprintCallable function on the `UUserWidget` itself (e.g., `SetIndicatorColor(FLinearColor Color)`) and calling that, allowing the widget to handle its own internal visual updates.
    ```cpp
     void UCounterIndicatorComponent::ApplyColor(const FLinearColor& Color)
     {
    -       // The widget should implement color changing logic
    -       // For now, we can use the widget's color and opacity property
    -       SetTintColorAndOpacity(Color);
    +       // The widget should ideally implement its own color changing logic for flexibility.
    +       // For example, if IndicatorWidgetClass exposes a BlueprintCallable function 'SetIndicatorColor'.
    +       // For now, relying on the UWidgetComponent's tinting.
    +       // Consider adding a Blueprint event dispatcher that the UMG widget can bind to.
    +       if (UUserWidget* Widget = GetWidget())
    +       {
    +               // Example: If the widget has a custom function.
    +               // IMyIndicatorWidget::Execute_SetIndicatorColor(Widget, Color);
    +               SetTintColorAndOpacity(Color); // Fallback or direct tinting.
    +       }
     }
    ```
