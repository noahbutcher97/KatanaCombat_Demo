## 6. Gaps & Bugs

### BUG-1: Combo Race Condition (INPUT-1)
*   **Priority**: 🔴 **Critical** | **Impact**: Gameplay Flow
*   **Description**: `CurrentAttackData` is set *after* `PlayAttackMontage` in `ExecuteAction`. If `PlayAttackMontage` triggers an immediate `OnMontageEnded` (via `StopAllMontages`), the state is cleared by `SetPhase(None)` before the new attack is registered. (Gap 25.1, 25.2, 25.3, 25.4). This violates the **Atomicity** of state transitions.
*   **Fix**: 
    *   **Rationale**: Ensure the state machine knows about the new attack *before* it can receive cleanup callbacks from the engine.
    *   **Snippet**:
        ```cpp
        // In ExecuteAction (Line 983-994)
        CurrentAttackData = Action.AttackData;  // Set FIRST
        if (PlayAttackMontage(Action.AttackData)) {
            SetPhase(EAttackPhase::Windup);
            DiscoverCheckpoints();
        } else {
            CurrentAttackData = nullptr;  // Revert on failure
        }
        ```

### BUG-2: Timeline/Timer Drift (Gap 26.10)
*   **Priority**: 🔴 **Critical** | **Impact**: Gameplay Sync
*   **Description**: `GetHoldDuration()` uses `GetWorld()->GetTimeSeconds()`, which is World Time. Animations use Anim Time. In slow-motion (Time Dilation), the hold duration counts faster than the animation, causing premature attacks. This leads to **Desynchronization with Animation**.
*   **Fix**: Use `UAnimInstance::GetActiveMontageRemainingTime()` or `GetWorld()->GetAudioTimeSeconds()`.

### BUG-3: GetWorld() Null Crash (Gap 22.1)
*   **Priority**: 🔴 **Critical** | **Impact**: Stability
*   **Description**: `GetHoldDuration()` does not verify `GetWorld()` before calling `GetTimeSeconds()`.
*   **Fix**: Add null check for `World` (Line 3163).

### BUG-4: `bExecutingAttackTransition` is improperly cleared.
*   **Priority**: 🔴 **Critical** | **Impact**: Race Condition Reintroduction
*   **Description**: The `bExecutingAttackTransition = false;` is cleared *before* the `if (bSuccess && Action.AttackData->AttackMontage)` block in `ExecuteAction`. If `PlayAttackMontage` fails (`bSuccess` is false), the `CurrentAttackData` and `CurrentAttackInputType` are reverted *after* this point. This creates a window where `SetPhase(None)` could still incorrectly clear the `CurrentAttackData`, reintroducing the race condition.
*   **Fix**: Clear `bExecutingAttackTransition` *after* all conditional logic related to the transition is complete (i.e., after the `if/else` block handling `bSuccess`).
    ```cpp
           // Clear guard flag - stale callbacks from StopAllMontages are now processed
    -       bExecutingAttackTransition = false;
    +       // If successful, discover checkpoints for the new montage
            if (bSuccess && Action.AttackData->AttackMontage)
            {
                    // Transition to Windup phase (event-driven phase management)
                    SetPhase(EAttackPhase::Windup);
    
                    DiscoverCheckpoints(Action.AttackData->AttackMontage);
    
                    // CRITICAL FIX: Reset hold state for new attack (clears bActivatedThisAttack)
                    HoldState.Reset();
    
                    // MOTION WARP: Setup warp based on context (target or direction)
                    SetupAttackWarp(Action.AttackData);
            }
            else
            {
                    // INPUT-1 FIX: Revert pre-set state on failure
                    CurrentAttackData = PreviousAttackData;
                    CurrentAttackInputType = PreviousInputType;
    
                    if (GetDebugDraw())
                    {
                            UE_LOG(LogCombat, Warning, TEXT("[EXECUTE] PlayAttackMontage failed - reverted CurrentAttackData to %s"),
                                    PreviousAttackData ? *PreviousAttackData->GetName() : TEXT("None"));
                    }
            }
    +       // Clear guard flag after all transition logic
    +       bExecutingAttackTransition = false;
            break;
    ```

### BUG-5: Incorrect `SetPhase(None)` condition at `OnMontageEnded`.
*   **Priority**: 🔴 **Critical** | **Impact**: Stale State / Combat Flow
*   **Description**: The line `if (!AttackStateMachine.IsComboBlending() && CurrentPhase != EAttackPhase::Windup && CurrentPhase != EAttackPhase::Active)` checks `!AttackStateMachine.IsComboBlending()`. This effectively skips setting `CurrentPhase = None` if the state machine reports `IsComboBlending()`. This can lead to `CurrentAttackData` remaining set even when no attack is active, causing stale state.
*   **Fix**: Use `BlendTransitionEndTime` or a more explicit "no longer in active combat" flag to decide when to set `Phase = None`.
    ```cpp
           // Phase transition to idle if not in combo blend
    -       if (!AttackStateMachine.IsComboBlending() &&
    +       if (GetWorld() && GetWorld()->GetTimeSeconds() >= BlendTransitionEndTime &&
                    CurrentPhase != EAttackPhase::Windup &&
                    CurrentPhase != EAttackPhase::Active)
            {
                    SetPhase(EAttackPhase::None);
            }
    ```

### GAP-1: Delegate Leak Hazard (Gap 11.5)

### GAP-3: `SetInputContext` and `ClearHoldState` should be part of `AttackStateMachine` reset.
*   **Priority**: 🟠 **High** | **Impact**: Input Lock / Stale State
*   **Description**: `SetInputContext(EInputContext::Movement);` and `ClearHoldState();` are crucial for resetting input/hold state after an attack. They are skipped if `bExecutingAttackTransition` is true. This can leave the input context or hold state in an incorrect (locked) state, especially during the race condition window.
*   **Fix**: These actions should ideally be part of a robust attack state cleanup, perhaps within `AttackStateMachine.OnMontageEndProcessed` or a dedicated cleanup function that is called unconditionally when an attack definitively ends.
    ```cpp
                            // INPUT-1 FIX: During combo transitions, StopAllMontages(0.0f) triggers
                            // OnMontageEnded -> SetPhase(None) synchronously. The new attack data is
                            // already set on CurrentAttackData — don't clear it.
                            if (!bExecutingAttackTransition)
                            {
                                    // Attack finished - reset combo state for next attack
                                    CurrentAttackData = nullptr;
                                    CurrentAttackInputType = EInputType::None;
    +
    +                               // CRITICAL: Ensure input context returns to Movement on attack completion
    +                               // This prevents directional input context leaking into idle/movement state
    +                               SetInputContext(EInputContext::Movement);
    +
    +                               // CRITICAL: Clear hold state completely (ease timer, flags, movement)
    +                               // This prevents hold state leaking into next attack
    +                               ClearHoldState();
    
                                    if (GetDebugDraw())
                                    {
                                            UE_LOG(LogCombat, Log, TEXT("[PHASE] Attack finished - Combo state, hold state, and input context cleared"));
                                    }
                            }
    ```

### GAP-8: Blending Overlap (Quick Win)
*   **Priority**: 🟢 **Quick Win** | **Impact**: Cinematic Feel
*   **Description**: Combo transitions use default blend-out times, causing root motion "sliding" when two montages overlap weights.
*   **Fix**: In `PlayAttackMontage`, if `bIsCombo` is true, force `PreviousMontage` to stop with 0.0f blend out.

### GAP-9: Cleanup Latency (Quick Win)

*   **Description**: `CurrentAttackData` is cleared in `OnMontageEnded`. This includes the "Blend Out" duration, making the character feel "locked" after the animation visually ends.
*   **Fix**: Move state reset to `OnMontageBlendingOut`.
