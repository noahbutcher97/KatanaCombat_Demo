# Code Review: AnimNotifyState_PairedAnimationCollision.cpp (2026-02-06)

## 1. Objective
Manages collision states during sync animations (finishers). Prevents characters from colliding with each other or the world while playing paired montages.

## 2. Scope
Collision and Movement mode modification.

## 3. Metrics & Standards
*   **Metrics**:
    *   Complexity: High (State restoration logic is complex).
*   **Standards Adherence**:
    *   Style & Naming: 🟢.

## 4. Code Organization
*   **Component Cohesion**: High.
*   **Dependency Flow**: Depends on `CombatComponent` for partner list.

## 5. Key Areas
*   **Functionality**:
    *   Targeted collision ignore (ignores specific partners).
    *   Dynamic obstruction scanning (prevents getting stuck in walls/other enemies).
    *   State restoration on End (critical).
*   **Safety**: Uses `TWeakObjectPtr` to track ignored actors.

## 6. Gaps & Bugs
### GAP-1: Restoration on Interrupt
*   **Priority**: Medium | **Impact**: Gameplay
*   **Description**: If the character dies or the component is destroyed *before* `NotifyEnd` fires, `RestoreState` might not run correctly (though `EndPlay` in `CombatComponent` attempts cleanup).
*   **Fix**:
    *   **Rationale**: Ensure collision is restored even on hard crashes/destroys.
    *   **Snippet**: Ensure `CombatComponent::EndPlay` explicitly restores collision if this notify was active.
