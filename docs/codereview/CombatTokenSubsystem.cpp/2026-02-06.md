## 6. Gaps & Bugs

### BUG-1: Token Leak on Destroy
*   **Priority**: 🟠 **High** | **Impact**: AI Deadlock
*   **Description**: If an actor is destroyed while holding a token, `ActiveAttackers` count remains decremented only until the next `CleanupInvalidActors()` call.
*   **Fix**:
    *   **Rationale**: Proactive cleanup is better than lazy cleanup for critical permits.
    *   **Action**: Ensure `ReleaseAttackToken` is explicitly called in the actor's `BeginDestroy` or `EndPlay`.

### GAP-1: Cooldown Reshuffle Loop
*   **Priority**: 🟡 **Medium** | **Impact**: Performance
*   **Description**: `TryGrantQueuedToken` puts actors back at the end of the queue if they are on cooldown. In a small group, this can cause unnecessary queue shuffling every time a token is released.
*   **Fix**: 
    *   **Rationale**: Avoid cyclic shuffling.
    *   **Snippet**: Implement a `WaitTime` check before processing the queue.

### GAP-2: Thread-Safety Concern
*   **Priority**: 🟡 **Medium** | **Impact**: Stability (Future)
*   **Description**: `CleanupInvalidActors` iterates and modifies `ActiveAttackers` (a `TArray`) without a lock or a deferred-removal queue. While safe in current single-threaded logic, it violates thread-safety best practices for systems likely to scale to async tasks.
*   **Fix**: Use a "Dirty Flag" or a separate `ToRemoval` list to prevent concurrent modification exceptions.

## 7. Action Items
*   **[Robustness]**: Implement a timeout for tokens to prevent permanent occupation.
*   **[Stability]**: Refactor cleanup logic to be thread-safe.
