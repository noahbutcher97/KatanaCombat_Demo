## 1. Objective
Provides static utility functions to query montage state, control playback, discover event checkpoints, and resolve next attacks in a combo chain.

## 2. Scope

## 5. Key Areas
*   **Functionality**:
    *   `DiscoverCheckpoints`: **Central to the animation-driven combat system.** It parses a montage's notifies to build a timeline of `FTimerCheckpoint` events. This is where the shift from `AnimNotifyState_HoldWindow` to `AnimNotify_HoldWindowStart` needs to be reflected. It correctly identifies `AnimNotify_AttackPhaseTransition` events.
    *   `ResolveNextAttackContextual`: Implements the priority-based logic for determining the next attack in a combo.
    *   `CalculateChargeLevel` / `GetMultiStageHoldPlayRate`: Provide robust helpers for the new timer-based hold mechanics, allowing scaling attack damage/playrate based on hold duration.
    *   `LoopMontageSection`: Critical for implementing charge loops for heavy attacks in the new hold system.

## 6. Gaps & Bugs

### GAP-1: Deprecated Hold Window Discovery
*   **Priority**: 🟡 **Medium** | **Impact**: Code Cleanliness / Debugging
*   **Description**: `DiscoverCheckpoints` explicitly scans for `AnimNotifyState_ActionWindow_Base` subclasses. While `AnimNotifyState_HoldWindow` is deprecated, this method will still log its discovery if present in montages. This creates confusion and potentially misleading debug output.
*   **Fix**:
    *   **Rationale**: The new hold mechanic is event-driven via `AnimNotify_HoldWindowStart`. `DiscoverCheckpoints` should either explicitly ignore deprecated window types or `AnimNotifyState_HoldWindow` should be removed from all montages and the class deleted entirely.

### GAP-2: Missing Actor-Relative Direction Transformation
*   **Priority**: Low | **Impact**: Gameplay Precision
*   **Description**: `GetDirectionFromInput` calculates an actor-relative direction, but the `ActorRelativeInput.Normalize()` call loses magnitude information, which could be useful for deadzone calculations or intensity scaling.
*   **Fix**:
    *   **Rationale**: Maintain maximum information fidelity before normalization.
    *   **Action**: Store the magnitude before normalization and pass it as an `Out` parameter or in a return struct.
