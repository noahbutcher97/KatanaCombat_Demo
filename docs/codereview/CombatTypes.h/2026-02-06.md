# Code Review: CombatTypes.h (2026-02-06)

## 1. Objective
Primary type definition header for the Combat System. Defines the central vocabulary (Enums and Structs) for state, input, and hit data.

## 2. Scope
Public enums and structs used across all combat modules.

## 3. Metrics & Standards
*   **Metrics**:
    *   Complexity: 🔴 **High** (Large header with 15 Enums and 10+ Structs).
    *   Test Coverage: N/A (Declarations only).
*   **Standards Adherence**:
    *   Style & Naming: 🟢 Standard UE PascalCase.
    *   Patterns: 🟡 **Architecture Risk** (High header coupling).

## 4. Code Organization
*   **Component Cohesion**: Low. Mixes high-level logic states (`ECombatState`) with low-level animation math types.
*   **Dependency Flow**: Central hub. Almost every file in the project depends on this header.

## 5. Key Areas
*   **Functionality**:
    *   `FAttackStateMachine`: Excellent implementation of a localized state machine to handle engine-level callback filtering (Same-montage section protection).
    *   `FHitReactionInfo`: Currently a bottleneck for hit registration data.

## 6. Gaps & Bugs

### GAP-1: Enum Bloat
*   **Priority**: 🟡 **Medium** | **Impact**: Compile Times
*   **Description**: This header contains too many unrelated types (e.g., `ETimingFallbackMode` for editor tools mixed with `ECombatState` for runtime).
*   **Fix**: Move editor-specific enums to a dedicated `CombatEditorTypes.h`.

### GAP-2: Missing Hit Analytics (Gap 24.3)
*   **Priority**: 🟠 **High** | **Impact**: VFX/Juice
*   **Description**: `FHitReactionInfo` is missing `WeaponVelocity` and `AnimationTime` fields.
*   **Fix**: Add `float AnimationTime; FVector WeaponVelocity;`.

### GAP-3: `ESpecialReactionType::GuardBroken` is confusing.
*   **Priority**: 🟡 **Medium** | **Impact**: Code Clarity
*   **Description**: `ESpecialReactionType::GuardBroken` is marked `(Deprecated)` but its `DisplayName` is still "Guard Broken". It's being superseded by `ESpecialReactionType::Staggered`.
*   **Fix**: For clarity and to prevent confusion with the old system, the `DisplayName` should reflect its deprecated status or explicitly state it forwards to `Staggered`.
    ```cpp
    enum class ESpecialReactionType : uint8
    {
    -    GuardBroken     UMETA(DisplayName = "Guard Broken"),
    +    GuardBroken     UMETA(DisplayName = "Guard Broken (Deprecated - Use Staggered)"),
        Staggered       UMETA(DisplayName = "Staggered"),
    ```

### GAP-4: Deprecated `FOnPostureChanged` and `FOnGuardBroken` delegates.
*   **Priority**: Low | **Impact**: Cleanup
*   **Description**: The delegates `FOnPostureChanged` and `FOnGuardBroken` are explicitly marked as `DEPRECATED` due to the removal of the posture system.
*   **Fix**: These delegates should be removed from `CombatTypes.h` as they are now dead code.

## 7. Action Items

*   **[Implementation]**: Expand `FHitReactionInfo` metadata.
*   **[Cleanup]**: Update `DisplayName` for `ESpecialReactionType::GuardBroken`.
*   **[Cleanup]**: Remove deprecated delegates.
