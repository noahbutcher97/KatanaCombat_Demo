# Portable animation analysis: first implementation

The existing geometry, raster, pixel and visual-review services now have an independently installable Python package in [Tools/AnimationAnalysis](../../Tools/AnimationAnalysis/README.md). Four existing review/calibration commands call that package. Katana is a consumer of these services; their implementation no longer resides in the project compatibility modules.

This is the first implementation slice of the [whole-suite migration](../architecture/ANIMATION_ANALYSIS_SUITE.md). Native capture, project evaluation/launching and paired preview integration remain project-coupled and are not represented as extraction-ready.

This audit retains the first-slice evidence. The subsequent [shared-service migration](SHARED_ANALYSIS_SERVICES_2026-09-11.md) extends the package to version 0.2.0 and records the current tests and provenance behavior.

## Boundary and compatibility

- `animation_analysis.contracts`: explicit clock domains, subject/stream/frame/pose identity and projection conventions. Row-major storage supports declared row or column multiplication and vertical NDC orientation. Different clock domains cannot be subtracted implicitly.
- `geometry`, `surfaces`, `pixel_alignment`, `images`, `evidence`, `reviews`: package-owned measurement and evidence services. Core imports have no game, Unreal-runtime, project-path or optional image dependency. The existing pixel/raster/decoder implementations were moved without algorithm changes.
- `adapters.unreal_capture`, `adapters.unreal_surface`: interpretation of current Unreal pose/projection and bounded surface records. Their assumptions are explicit producer-format boundaries, not shared role/skeleton defaults.
- `adapters.legacy_evidence`: historical montage/simulation clock normalization into canonical evidence schema 2. Original input bytes and SHA256 remain authoritative. Canonical records use `time: {domain, seconds}`. Conflicting clocks and unsupported schema versions reject.
- `jobs.visual_review`, `jobs.surface_review`, `jobs.segment_calibration`, `jobs.segment_detection`: callable services and installed console entry points. They accept explicit input/output paths from outside the checkout. Surface review now emits canonical evidence; native bundle format and numeric results are unchanged.
- `Tools/CombatCapture/visual_analysis/*.py` and the four old commands: thin compatibility delegates. The checkout-specific import resolution lives here. Katana profiles remain here as integration data and are absent from the wheel.

Distribution metadata uses the standard [Python packaging contract](https://packaging.python.org/en/latest/guides/writing-pyproject-toml/) with a `src` layout, no required runtime dependencies and an optional pinned Pillow extra. No distribution was published externally.

## Remaining work

The next migration is capture integrity/identity and common evaluation/comparison/publication from `analyze_capture.py`, `evaluate_capture.py`, `summarize_runs.py` and the runners, separating combat assertions and project launch/asset discovery. Native recorder/telemetry separation and an engine-only build boundary follow. Existing preview/commandlet, generalized retention, async depth readback, moving skeletal sampling and geometric penetration remain explicit work in the suite plan.

This Python migration does not improve capture performance or establish new runtime/visual contact results. No C++ build or Unreal automation run was needed for it. Source/config is unchanged; all 7,948 Content files retain their starting size/mtime and all 54 protected asset paths retain their hashes or missing-file state. `verification.json` records these checks, exact current package/wheel identity and 28 local documentation links. No new PNG exports were created; portable HTML retains replay output, the verified wheel is retained, and isolated build/install scratch is removed.
